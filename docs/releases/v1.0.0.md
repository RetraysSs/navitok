# navitok 1.0.0

navitok is a Claude Code plugin that plans a project into releases that each fit your plan's 5-hour session and weekly usage limits. It keeps the schedule current as your real usage changes, including claude.ai and other machines, and it calibrates its estimates from your own history.

## Install

```text
/plugin marketplace add RetraysSs/navitok
/plugin install navitok@navitok
/navitok:setup
```

Needs Python 3.10+ (standard library only). Tested with Claude Code 2.1.332 on Windows 11: marketplace add and install from GitHub, and `/navitok:plan` end to end in an empty folder.

## What's in 1.0

- **`/navitok:plan`:** splits a project into releases of 3–5 tasks. A script prices each task as a range of session % with a confidence score, and no release is planned past the stop threshold (90% at cold start, never above 98%). Strict and flex modes.
- **Fit check before every task:** if the next task no longer fits, navitok says so in one line and offers `/navitok:checkpoint` (a clean commit plus a handoff) instead of a half-finished prompt.
- **Live schedule:** account-wide session and weekly % come from the statusline (or a `/usage` reading). External usage is shown separately and never counted as estimation error.
- **Calibration:** sessions are recorded locally. Ranges and the threshold calibrate to your history.
- **`/navitok:setup`:** a doctor table (✅/❌, why each item helps, the command to fix it) and a first-run wizard. Nothing is installed or changed without your approval.
- **Statusline segment and terminal panel:** zero tokens, local files only. An existing statusline is wrapped, never replaced.
- **`/navitok:status`** and **`/navitok:checkpoint`**, with handoff resume at the next session start.
- **Works with Superpowers** (plan import) **and Graphify** (file-level scoping): both optional third-party tools, detected and read only, never installed or changed.
- **Optional output trimming:** a `PostToolUse` hook for long output of commands that succeed, and `scripts/run.py` for tests and builds (Claude Code gives no `PostToolUse` to commands that exit non-zero). Off by default; costs about 20 ms per Bash call while off.

## Built with navitok

16 measured sprints before this release, each estimated as ranges before any work and measured from `/usage` after the last commit. The first 9 sprints (v0.0–v0.8) landed inside their range 2 times out of 9, with a mean absolute error of 6.1 points. The last 7 (v0.9–v1.0a) landed inside 7 of 7, with a mean absolute error of 2.1. The estimates still lean high, which is the intended direction. The data covers one maintainer, one plan and one project: see `docs/dogfood/REPORT.md`.

## Known limitations

- Without a statusline, a manual `/usage` reading can be overwritten by the stale usage cache at the next prompt. Setting up the statusline (offered by `/navitok:setup`) avoids it.
- When `/navitok:plan` creates `.navitok/` partway through a session, that first session can be recorded with 0 local tokens.
- The `curses` panel has not been run live on Linux or macOS yet (Windows uses an ANSI fallback).
- No screenshots or plugin icon yet; the README shows real text output instead. Images are planned for 1.0.1.

> Estimates rely on personal calibration and are not guarantees. Anthropic's limits may change. Usage from other devices is detected only through account-wide numbers.
